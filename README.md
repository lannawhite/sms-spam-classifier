## Why build it from scratch

It is trivial to fine-tune `bert-base-chinese` and report 98%. The point of this project was to understand
the **most elementary NLP pipeline end to end** — how a raw sentence becomes a fixed-length vector, how an
embedding table is learned from zero, and what a plain feed-forward classifier can and cannot capture.

Building every stage by hand makes the failure modes visible, which is the whole point of the exercise:

- **Out-of-vocabulary words** — the dominant failure mode for word-level tokenisation (every unseen word collapses to `UNK`)
- **Fixed-length truncation** — messages longer than 50 tokens get cut; shorter ones get padded, diluting the signal
- **No word order** — a fully-connected head sees each message as a bag of fixed-length token ids; it cannot tell *"not spam"* from *"spam not"*

## Architecture

```
raw SMS
  │
  ├─ jieba.lcut(text)                  word segmentation
  ├─ Word2Sequence                     vocab build (UNK=0, PAD=1, min_count filter)
  │                                  → fixed-length 50 ids (pad / truncate)
  ├─ Embedding(100000, 100)           (batch,50) → (batch,50,100)
  ├─ flatten                          (batch,50,100) → (batch,5000)
  ├─ Linear(5000 → 500) + sigmoid
  ├─ Linear(500 → 2)   + sigmoid     logits over [spam, ham]
  └─ CrossEntropyLoss, predict = argmax
```

> `label` mapping (see `datasets.py`): `ham → 1`, `spam → 0`, so the output logit is `[spam, ham]`.

## Project structure

```
sms-spam-classifier/
├── SMSSpamCollection     # dataset (UCI), 5572 lines, label<TAB>text
├── word2sequence.py      # custom vocab builder (fit / build_vob / transform) + pickle dump
├── smsspam.data          # prebuilt vocabulary (generated by word2sequence.py)
├── datasets.py           # torch Dataset: load + tokenise + 9:1 train/test split

├── requirements.txt
└── README.md
```

## Quick start

```bash
pip install -r requirements.txt

# 1. (optional) rebuild the vocabulary — smsspam.data is already included
python word2sequence.py

# 2. train — prints loss + test accuracy every 4 epochs, saves model_output/best.pt
python train.py

# 3. classify a message
python predict.py "Free entry in 2 a wkly comp to win FA Cup final tkts"
# → [spam] (spam=0.xxxx)  ...
```

## Honest limitations

- `jieba` is a **Chinese** word segmenter. For English SMS, whitespace + regex tokenisation would be more
  idiomatic — a clean swap to make.
- The fixed length of 50 truncates long messages and pads short ones.
- A fully-connected head ignores word order; some spam patterns (negation, emphasis) are order-sensitive.
